# Как собрать .exe-инсталлятор АБИЗ и раздать его сотрудникам

Инструкция рассчитана на то, что ты делаешь это первый раз. Выполняй по порядку,
не пропуская шаги. Весь процесс занимает 30–40 минут в первый раз и 2 минуты
при последующих сборках.

---

## Часть 1. Что установить один раз

### 1.1. Visual Studio 2026 с нужными компонентами

Открой **Visual Studio Installer** → у установленной VS 2026 нажми **Изменить** →
на вкладке **Рабочие нагрузки** поставь галочку:

- ✅ **Разработка классических приложений .NET** (.NET desktop development)

На вкладке **Отдельные компоненты** убедись, что есть:

- ✅ **.NET 8.0 Runtime** и **.NET SDK**

Нажми **Изменить** и дождись установки.

### 1.2. Расширение WiX для Visual Studio

WiX — это бесплатный конструктор установщиков Windows. Ставим его в двух местах.

**а) Инструмент командной строки.** Открой **PowerShell** (от обычного пользователя) и выполни:

```
dotnet tool install --global wix --version 5.0.2
```

Проверь, что встало:

```
wix --version
```

Должно напечатать `5.0.2+...`. Если PowerShell пишет, что команда `wix` не найдена —
закрой и открой PowerShell заново (обновляется переменная PATH).

**б) Расширение для студии.** В Visual Studio: **Расширения → Управление расширениями**
→ вкладка **В сети** → найди в поиске `HeatWave` → установи **HeatWave for VS2026**
(бесплатное community-издание). Студия попросит перезапуститься — согласись.

> Зачем оно: без него файлы `.wixproj` откроются как текст, а не как проекты,
> и в студии не будет кнопки «Собрать» для установщика.

### 1.3. Два установочных файла для бандла

Итоговый `.exe` будет сам доустанавливать на ПК сотрудника то, без чего программа
не запустится. Эти два файла надо скачать вручную и положить в проект.

Создай папку `desktop-app\installer\redist` и скачай в неё:

1. **Microsoft Edge WebView2 Runtime** (движок встроенного браузера)
   Скачай «Evergreen Bootstrapper» со страницы:
   `https://developer.microsoft.com/microsoft-edge/webview2/`
   Переименуй скачанный файл ровно в: `MicrosoftEdgeWebview2Setup.exe`

2. **.NET 8 Desktop Runtime x64** (среда выполнения программы)
   Скачай «Desktop Runtime» для x64 со страницы:
   `https://dotnet.microsoft.com/download/dotnet/8.0`
   Переименуй файл ровно в: `windowsdesktop-runtime-8.0-win-x64.exe`

В итоге должно получиться так:

```
desktop-app\
  installer\
    redist\
      MicrosoftEdgeWebview2Setup.exe
      windowsdesktop-runtime-8.0-win-x64.exe
```

> Имена файлов важны — они прописаны в `Bundle.wxs`. Если назовёшь иначе,
> сборка упадёт с ошибкой «file not found».

## Часть 2. Сборка (три команды)

Открой **PowerShell** и перейди в папку проекта. Например, если распаковал на диск C:

```
cd C:\AbizShell\desktop-app
```

### Шаг 1. Опубликовать программу

```
dotnet publish AbizShell\AbizShell.csproj -c Release -r win-x64 --self-contained false
```

Эта команда собирает программу и складывает все нужные файлы в одну папку.
Должно закончиться строкой `Сборка успешно завершена` / `Build succeeded`.

Проверь, что файл появился:

```
dir AbizShell\bin\Release\net8.0-windows\win-x64\publish\AbizShell.exe
```

### Шаг 2. Собрать MSI-пакет

```
dotnet build installer\AbizInstaller.wixproj -c Release
```

Создаст `installer\bin\Release\AbizSetup.msi`.

### Шаг 3. Собрать итоговый .exe

```
dotnet build installer\AbizBundle.wixproj -c Release
```

**Готово.** Твой инсталлятор лежит здесь:

```
desktop-app\installer\bin\Release\AbizSetup.exe
```

Это один самодостаточный файл (~150–200 МБ, потому что внутри .NET и WebView2).
Именно его раздаёшь сотрудникам.

### Удобно: один скрипт вместо трёх команд

В папке `desktop-app` есть файл `build-installer.ps1`. Запусти его — он выполнит
все три шага подряд и скажет, где лежит результат:

```
powershell -ExecutionPolicy Bypass -File build-installer.ps1
```

## Часть 3. Сборка из интерфейса Visual Studio (альтернатива)

Если не хочешь командной строки:

1. **Файл → Открыть → Проект/решение** → выбери `AbizShell\AbizShell.csproj`.
2. В **Обозревателе решений** правой кнопкой по решению → **Добавить → Существующий проект**
   → добавь `installer\AbizInstaller.wixproj`, затем так же `installer\AbizBundle.wixproj`.
3. Сверху переключи конфигурацию с **Debug** на **Release**.
4. Правой кнопкой по проекту `AbizShell` → **Публикация** → профиль: папка,
   целевая среда `win-x64`, режим `Зависит от платформы` → **Опубликовать**.
5. Правой кнопкой по `AbizInstaller` → **Собрать**.
6. Правой кнопкой по `AbizBundle` → **Собрать**.

Результат — там же: `installer\bin\Release\AbizSetup.exe`.

> Порядок важен: публикация → MSI → бандл. Бандл берёт готовый MSI, а MSI берёт
> опубликованные файлы. Если собрать не в том порядке, будет ошибка про отсутствующий файл.

## Часть 4. Как раздать на ПК сотрудников

### Вариант А. Вручную (1–5 компьютеров)

1. Скопируй `AbizSetup.exe` на флешку или выложи в Базу документов на сайте
   (**Документы → Загрузить файл**) — тогда файл можно будет скачать на каждом ПК по ссылке.
2. На компьютере сотрудника запусти файл **правой кнопкой → Запуск от имени администратора**.
3. Пройди шаги установщика (принять условия → Установить).
4. **Перезагрузи компьютер.** После перезагрузки АБИЗ запустится автоматически
   и покажет экран пароля.
5. На экране будет **9-значный код устройства**. Запиши его.
6. Зайди на сайте `anod.saou.ru` под директором → **Сотрудники → Устройства** →
   найди этот код → **Привязать** → выбери сотрудника → при необходимости задай пароль.
7. Программа на ПК сама увидит привязку в течение 5 секунд и перейдёт к вводу пароля.
   Пароль сотрудника: `243063`, пароль администратора: `832605633`.

### Вариант Б. Через групповые политики (много компьютеров в домене)

1. Положи `AbizSetup.msi` (не .exe!) в сетевую папку с доступом на чтение для всех ПК,
   например `\\server\install$\AbizSetup.msi`.
2. На контроллере домена: **Управление групповой политикой** → создай новый объект GPO
   → **Конфигурация компьютера → Политики → Конфигурация программ → Установка программ**
   → правой кнопкой → **Новый → Пакет** → укажи UNC-путь к MSI → метод **Назначенный**.
3. Привяжи GPO к нужному подразделению (OU) с компьютерами сотрудников.
4. Программа установится сама при следующей перезагрузке каждого ПК.

> Для варианта Б на ПК должны быть заранее установлены .NET 8 Desktop Runtime и
> WebView2 — MSI, в отличие от .exe-бандла, их не ставит. Их тоже можно раздать
> через GPO отдельными пакетами, либо просто использовать Вариант А.

## Часть 5. Проверка, что всё работает

После установки на тестовом ПК проверь по списку:

| Что проверяем | Как | Ожидаемый результат |
|---|---|---|
| Автозапуск | Перезагрузить ПК | АБИЗ открылся сам на весь экран |
| Привязка | Посмотреть на экран пароля | Виден 9-значный код устройства |
| Автовход | Ввести пароль сотрудника | Сразу открылся личный кабинет без ввода логина |
| Меню кнопок | Нажать **Tab** или дважды **Пробел** | Поверх сайта появились плитки приложений |
| Закрытие меню | Выбрать любую кнопку | Меню само скрылось, открылся сайт/программа |
| Панели | Смотреть при переключениях | Верхняя и нижняя панели не мигают, видны всегда |
| Печать | Нажать иконку принтера сверху | Открылся диалог печати Windows |
| Блокировка | Нажать замок внизу | Вернулся экран ввода пароля |
| Админ-меню | Войти паролем админа | Появилась шестерёнка сверху |
| Редактор кнопок | Шестерёнка → Изменить кнопки киоска | Можно двигать стрелками и сохранить |
| Выход в Windows | Шестерёнка → Выйти в Windows | Программа закрылась, виден рабочий стол |

## Часть 6. Если что-то пошло не так

**«wix: команда не найдена»**
Закрой и открой PowerShell. Если не помогло — проверь, что папка
`%USERPROFILE%\.dotnet\tools` есть в переменной PATH.

**«The file ... was not found» при сборке бандла**
Не выполнен Шаг 1 или Шаг 2, либо не скачаны файлы в папку `redist`.
Собирай строго по порядку: publish → MSI → bundle.

**Программа запустилась, но окно браузера белое/пустое**
Не установлен WebView2 Runtime. Поставь вручную файл
`MicrosoftEdgeWebview2Setup.exe` из папки `redist`.

**Windows показывает «Неизвестный издатель» при запуске .exe**
Это нормально для неподписанного установщика. Нажми **Подробнее → Выполнить в любом случае**.
Чтобы убрать предупреждение навсегда, нужен сертификат подписи кода (покупается
у аккредитованного центра, от ~15 000 ₽/год) — для внутренней программы обычно не берут.

**Нужно обновить программу на всех ПК**
Измени версию в `Product.wxs` и `Bundle.wxs` (например, с `1.0.0.0` на `1.0.1.0`),
собери заново и запусти новый `.exe` на ПК. Благодаря `MajorUpgrade` старая версия
удалится автоматически, настройки и привязка устройства сохранятся (они в реестре).

**Сотрудник сумел выйти из программы**
Полная блокировка Ctrl+Alt+Del и диспетчера задач средствами самой программы
невозможна — эти комбинации перехватывает сама Windows раньше любого приложения.
Правильное решение — включить штатный **режим киоска Windows** (Assigned Access)
поверх АБИЗ. Скажи, если нужно, — дам отдельную инструкцию по его настройке.
